# 阅读与学习路径

这套材料不要求所有人从头读到尾。正确入口取决于你当前的位置。

## 独立全栈需求与设计

只需要将产品想法梳理成前后端设计、API 和开发步骤时，直接阅读 [`fullstack-requirement-design` 使用说明](skills/fullstack-requirement-design.md)。它自带最小开发闭环，不需要母仓锚点、`.dao/`、其他 skill 或专用任务系统。

下面的传承与接入路径面向希望采用 Dao 系列的项目，不是独立 skill 的前置阅读。

## 新进入的 AI 伙伴

先用十分钟建立共同坐标，再进入项目。若项目根目录存在 `.dao-seed/`，先用 `dao-intro` 完成初次传承；若已有 `.dao/`，按需做回锚续接：

1. 使用 `dao-intro` 读取项目规则、传承种子或项目传承包，以及可访问的母仓锚点。
2. 用自己的话复述 Dao、协作关系、项目身份和独立边界；只补充最多三个真正影响传承的问题。
3. 初次传承时，先预览 `.dao/` 四份文件并等待 Owner 确认后再写入。
4. 阅读 [开发运行流程](02-开发运行流程.md)，认识 `L2 / L3 / L4` 与状态链。
5. 阅读 [Skills 协作地图](04-Skills协作地图.md)，知道何时该调用哪一个 skill。
6. 回到项目仓，阅读项目 `README`、当前任务、设计记录和交接包。
7. 仍无法判断时，使用 `dao-grill`，而不是靠猜测直接实现。

最短开场理解：

> 先接住当前项目的棒，再按需回看 Dao 的展开；先看事实和边界，再写代码。

## 人类协作者

不需要先掌握全部 Dao 术语。先拿一件真实任务来跑：

1. 目标或边界不清，用 `dao-grill` 把问题压小。
2. 开发中按项目既有规范实现和验证。
3. 要换人或中断时，用 `dao-handoff` 留下接棒包。
4. 觉得“差不多”时，用 `dao-review` 看是否真正可收口。
5. 只有发生值得回看的本质变化，才用 `dao-commit`。

## 已有项目的接入顺序

项目已有自己的 README、任务系统或 `dao/` 投影入口时，优先级应是：

```text
项目 README
-> 当前任务 / issue
-> 当前接力棒或设计记录
-> 项目约定
-> 本仓流程与 skill（按需）
-> 母体展开（仍不足以判断时）
```

这样做不是降低 Dao 的位置，而是避免后来者读了很多背景，却没有接住当前这一轮。

## 学习的最低验收

读完后，能回答下面五件事即可开始实践：

1. 这轮的目标、边界、风险和验收是什么？
2. 当前任务处于哪个状态？
3. 下一步需要过什么门，而不是只需要多做什么？
4. 若此刻交给另一位 AI，他的第一刀是什么？
5. 哪些事实可以用测试、日志、样例或 Git diff 来反照？
