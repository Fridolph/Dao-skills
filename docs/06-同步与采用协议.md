# 同步与采用协议

## 为什么需要这份协议

Dao skills 要从真实项目持续学习，但不能让每个项目、分发仓和本机安装目录各自演化成一份“正确答案”。

稳定内容只沿以下主线流动：

```text
实践来源 / dao-* 子项目
-> Dao-is-Coding（归母、定规范）
-> Dao-skills（打包、版本与分发）
-> 各项目选择性采用
```

`Dao-is-Coding` 是稳定规范与完整 skill 源包的权威；本仓是唯一可安装分发包与版本台账的权威。

## 项目怎样采用

1. 选择当前真正需要的 skill，而不是一次装全。
2. 复制或软链接完整 `skills/<skill>/` 目录，保留其中的 `references/`、协议和数据文件。
3. 项目自身的 `README`、任务、`dao/` 和 `.dao/` 仍然管理项目事实；skill 不夺取它们的主位。
4. 新 AI 或新项目先按 `dao-intro` 建立传承，再按需进入 `dao-grill`、`dao-handoff`、`dao-review` 等节点。

采用不是同步母仓状态，更不是将项目任务反写回 Dao；它只是让项目选择可用的稳定能力。

## 发现修正时怎样回提

在项目、本仓或安装目录发现问题时，先带回可判断的事实：

```text
来源项目 / 样本：
发现的差异或问题：
建议修正：
影响边界：
验证证据：
```

母仓判断其应留在项目、候选观察还是正式归母。确认归母后，才把更新后的完整包同步回本仓；不要只改分发包或本机安装目录。

## 分发校验

每次同步至少确认：

- skill 的目录、入口、引用资源和数据文件都已同步；
- 母仓源包与分发包目录级一致；
- 文档索引、触发边界和示例没有指向旧口径；
- 台账记录了来源、日期与已知例外。

当前的权威路径、版本基线与已知漂移见 [Skill 分发与版本台账](07-Skill分发与版本台账.md)。
