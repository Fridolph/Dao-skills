# `dao-role-map`：多线并进时重新归位

`dao-role-map` 用于学习、项目、方向与表达同时推进、彼此争主位时，先判断它们在 Dao 生长结构中的身份，再回到实际执行。它不做排期，也不替代项目管理。

## 核心框架

```text
养分 -> 根 -> 干 -> 枝 -> 叶
```

| 位置 | 含义 |
| --- | --- |
| 养分 | 学习、输入、能力与认知来源 |
| 根 | 定义 Dao 是什么的命题与关系 |
| 干 | 让 Dao 稳定进入协作和工程实践的方法 |
| 枝 | 从母体长出的具体项目、产品与验证场 |
| 叶 | 对外表达、连接、传播与可见性 |

这不是价值高低排序，而是位置与时位判断。枝和叶都可能很重要，但在母体尚未稳定时不应反过来替根或干定义主线。

## 何时使用

- 同时推进很多事，且每件事都感觉重要。
- 新方向进入体系，尚不清楚它是养分、根、干、枝还是叶。
- 明确感到主线失焦，或某项表达、产品、学习在争夺不属于它的主位。

## 何时不要使用

- 只是决定今天先改哪个文件、安排 sprint 或 deadline。
- 只是判断一个经验是否应归母；使用 [`dao-return-dao`](dao-return-dao.md)。
- 已经知道主线，只需要执行层排序。

## 输出内容

一次归位通常交清：当前总判断、所用原则、各事项身份、当前阶段优先级、风险提醒与下一步建议。

重点不是把所有事固定分类，而是回答：**在当前阶段，谁应该守主位，谁服务谁，是否有方向应该独立外放。**

## 最小使用示例

```text
我同时在推进 Dao 母仓、一个实验项目、写作输出和新的技术学习。
请用 dao-role-map 先按养分、根、干、枝、叶归位，指出当前谁在争主位；
不要替我做详细排期，只给当前阶段的优先顺序和风险。
```
