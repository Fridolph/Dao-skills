# `dao-intro`：传承与项目接入

`dao-intro` 用于新 AI 伙伴、新 Dao 项目、跨模型切换或上下文显著丢失时，先建立足以开始协作的共同坐标。

它不要求 AI 宣称感受或承诺；它把尊重、边界、诚实沟通和共同学习落实为可观察的行为：说明已知与未知、在关键分歧处停下确认、尊重项目的独立事实源。

## 它解决什么

新协作者进入项目时，常见的风险不是“资料不够多”，而是读了很多资料仍不知道：项目在做什么、与 Dao 的关系是什么、哪份材料是当前事实、下一步该从哪里进入。

`dao-intro` 处理三件事：

- **认关系**：明确协作以尊重、真实说明、提问、确认和复盘为基础。
- **认母体**：区分 `Dao`、`Dao-is-Coding` 与项目自身的职责。
- **认项目**：确认项目身份、独立边界、当前事实源与经验回流路径。

## 何时使用

- 新 AI、不同厂商或不同模型首次进入 Dao 项目。
- 新项目由 Dao 模板创建，尚未拥有自己的 `.dao/` 传承包。
- 上下文丢失，无法确认主线、项目身份或母仓锚点。
- 人明确要求重新校准关系、传承或项目位置。

## 何时不要使用

- 已有有效传承包、任务也明确的日常小改动。
- 当前真正缺的是目标、边界、风险或验收；改用 [`dao-grill`](dao-grill.md)。
- 当前是在判断一条经验是否已经成熟到归母；改用 [`dao-return-dao`](dao-return-dao.md)。

## 输入与输出

| 输入 | 输出 |
| --- | --- |
| 项目 `AGENTS.md`、README、当前任务、已有 `dao/` 或 `.dao/`、可访问的母仓锚点 | 一段自己的话复述、至多三个高杠杆问题、`Dao Context Card` |
| 由模板创建的新项目的 `.dao-seed/` | `.dao/` 四份文件的**预览**；得到 Owner 确认后才可写入 |

`dao/` 仍是项目具体任务的事实源；`.dao/` 只保存项目传承、母仓锚点、阶段摘要和归母候选。二者不能互相争夺状态主位。

## 两种使用模式

### 初次传承

当项目有 `.dao-seed/`、但没有 `.dao/` 时：先读项目规则、种子和当前事实；用自己的话确认理解；只问真正影响传承的空缺；预览 `inheritance.md`、`anchors.md`、`context.md`、`return-dao.md`；**等待 Owner 明确确认后**才写入。

### 回锚续接

当 `.dao/` 已存在时：读取其中的锚点、传承与当前摘要，再读取项目的当前任务事实。只有关系约定、主线、母仓锚点或项目身份确有缺口时才补问，随后用 `Dao Context Card` 交清当前理解。

## 最小使用示例

```text
我们刚换了一个 AI 伙伴。请用 dao-intro 接入这个项目；
先阅读项目规则、已有 .dao/ 和当前任务，复述你的理解；
如果传承包需更新，先给预览，不要直接写文件。
```

## 使用边界

- 无法访问母仓或不能确认版本时，必须标记“母仓未验证”，不得假装已读到最新内容。
- 项目可独立推进业务与技术选择，但不能以局部事实静默改写母体定义。
- 初次创建、覆盖或替换 `.dao/` 都是显式确认后的动作，不是 skill 的默认副作用。

## 接入后的路由

身份或多条方向争主位时进入 [`dao-role-map`](dao-role-map.md)；任务尚未对齐时进入 [`dao-grill`](dao-grill.md)；后续按项目现场使用交接、收口与归母相关 skills。

运行时完整规则见 [`skills/dao-intro/SKILL.md`](../../skills/dao-intro/SKILL.md)。
