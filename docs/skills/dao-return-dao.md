# `dao-return-dao`：经验何时归母

`dao-return-dao` 用于判断项目、分支或实验中出现的新规则、新命名、新流程和修订依据，今天应留在项目、作为候选继续观察，还是已经成熟到可以进入 Dao 母体。

它不是收纳工具。归母的目标是让母体更清楚，不是让母仓拥有更多内容。

## 三条最小标准

```text
1. 它能不能跨项目成立？
2. 它是不是已经被真实场景验证？
3. 它回去之后，会不会让母体更清楚？
```

只要其中一条明显站不住，就不要急着升级为正式规范。

## 何时使用

- 同类经验已经在两个或更多场景中出现。
- 项目实践持续冲击某项已有定义，且开始形成稳定修订依据。
- 有一条规则、流程或命名显然不再只属于当前项目。

## 何时不要使用

- 仅是一次灵感、普通复盘或单项目业务规则。
- 当前真正问题是项目或方向的身份归位；使用 [`dao-role-map`](dao-role-map.md)。
- 还没判断成熟度就急着讨论要写进哪个目录。

## 输出结论

只输出三类结论，避免暧昧升级：

| 结论 | 含义 | 下一步 |
| --- | --- | --- |
| 留在分支 | 仍依赖项目上下文或尚无充分验证 | 继续在项目记录样本 |
| 候选观察 | 有通用潜力，但证据尚不足 | 写明待验证条件与观察位置 |
| 可以归母 | 已跨项目成立、证据充分、能增加清晰度 | 提交归母卡并确定落点 |

归母卡至少包含来源样本、修正判断、跨项目理由、风险、拟落点和验收证据。完整协议见 [同步与采用协议](../06-同步与采用协议.md)。

## 最小使用示例

```text
我们在两个项目里都发现“项目任务事实不应和传承摘要争主位”。
请用 dao-return-dao 判断这条规则应留在项目、候选观察还是归母；
按三条标准给出证据与下一步，不要直接替我写成正式规范。
```

## 它不会替代什么

- 不评判整个项目是否应该回到母体。
- 不以“有价值”“很漂亮”替代真实验证。
- 不在尚未成熟时强行把内容器化为 skill。
