# `fullstack-requirement-design`：独立的全栈需求、设计与开发协作

从同一组业务场景出发，交清产品规则、前端交互、后端保证、API 契约和验证方式，再拆成能实际实现与验收的开发切片。

这个 skill 可独立运行，不依赖 Dao、其他 skill、任务卡系统、Issue 平台或固定分支模型。它也能适配已有流程：复用项目文档与工作记录，不另建一套竞争的事实源。

## 适用场景

- **需求分析**：只有产品想法，需要厘清角色、规则、边界、失败出口与验收。
- **技术设计**：需求已明确，需要前端、后端、数据和 API 的一致方案。
- **开发协作**：用户已授权实现，需要按场景逐片开发、联调、测试和交接。
- **变更评审**：规则变化后，判断哪些角色、契约、数据和验收需要同步。
- **文档重建**：已有代码，需要补齐需求、前后端技术设计和接口说明。
- **学习复盘**：沿真实场景理解设计、源码、测试和运行证据，适合全栈学习与教学。

## 何时不需要它

- 仅修一个明确的样式、文案或局部实现，不需要跨端需求与设计。
- 想直接替代语言、框架或测试工具的专业能力。
- 只想得到代码量、文档数量或无条件的“已完成”结论。

默认技术参考是 TypeScript monorepo 的 Nuxt/Next.js + NestJS；不强制框架、ORM 或数据库。其他技术栈沿用场景、契约和证据方法，按实际项目展开实现。

## 输入与输出

| 输入 | 对应交付 |
| --- | --- |
| 一段需求、参与者、目标与限制 | 共享场景、术语、业务规则、非目标、待确认问题、验收例子 |
| 已确认场景和现有系统约定 | 前端与后端设计、API 契约、必要的数据与兼容设计 |
| 实现授权与当前代码、接口和测试 | 纵向开发切片、实现与联调、验证结果及未验证边界 |
| 需求差异与原设计 | 变更影响、需修改/需知会/无影响的依据和复测范围 |
| 已有源码、文档及可用历史 | 当前实现重建、设计偏差、接口覆盖与证据缺口 |

没有代码或历史也可以开始；这时形成候选设计，不声称已核实实现。未确认的规则标为未决，不用推测填成产品决定。

## 一轮怎样运行

```text
核对材料与授权范围
→ 共享场景、规则与验收
→ 前端 / 后端 / API 视图
→ 可独立验收的开发切片
→ 按需实现、联调、测试
→ 交付证据、遗留问题与下一步
```

角色视角分别负责：

| 视角 | 核心问题 |
| --- | --- |
| 产品与交互 | 谁触发什么、得到什么；业务规则和可见状态是什么 |
| 前端 | 入口、组件、工作副本、请求、缓存、失败恢复与响应式交互如何组织 |
| 后端 | 身份、权限、所有权、校验、持久化、事务和并发由谁保证 |
| API | 路径、输入输出、可空/缺省、错误、幂等、上传下载与兼容如何约定 |
| 测试与运行 | 怎样证明场景成立；在哪个版本和环境测过，仍有哪些风险 |

每个视图引用相同场景，业务规则只定义一次。一个人承担多个角色时仍逐项审查；小任务裁剪输出，不要求为每个角色都建一份文档。

## 最小使用示例

### 没有既有流程，从一个产品想法开始

```text
请使用 fullstack-requirement-design 梳理活动报名系统。
普通用户可以报名和取消，管理员可以查看名单。
我们还没确定容量和取消规则，也没有代码或任务管理工具。
先做需求、前后端/API 设计方向和开发切片，暂不写代码。
```

期望结果：区分已知与未决，给出可确认候选和可验收的第一片，不要求先安装流程框架或建立特定目录。

### 设计确认后推进一条闭环

```text
上一轮已确认本场景的规则、权限和 API。
请用 fullstack-requirement-design 推进第一条报名闭环：
先核对现有实现，再做前后端和接口联调，执行相关测试；
记录已测环境与未验证项，部署另行决定。
```

### 从真实代码重建教学资料

```text
请用 fullstack-requirement-design 复盘文件上传与资料保存场景。
对照页面、接口 schema、Service 和测试，补需求及分角色设计。
区分期望规则、当前行为与实际验收证据；不要修改代码或虚构过去评审。
```

## 与其他 skills 的关系

可以单独安装使用；在采用 Dao 的项目中，也可与 `dao-grill` 的任务对齐、`dao-handoff` 的接力、`dao-review` 的收口检查组合。它们是可选组合，不是调用链依赖。

它不自动授权数据库迁移、外部平台写入、提交推送或部署。实际执行范围以用户请求和项目约定为准。

## 当前验证边界

本轮收录前已有结构校验、作者自查和真实项目试用记录；曾通过实际 schema 样本发现跨接口输入输出不兼容。此类证据说明一次试用能暴露问题，不能推出任何项目都有效。

已提供七类回归样本；独立模型行为评测尚未完成。使用时观察设计是否减少误解、能否直接交给实现，以及额外文档成本是否合理。维护源与同步记录见[版本台账](../07-Skill分发与版本台账.md)。
