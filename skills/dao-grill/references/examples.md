# dao-grill 示例集

## 示例 1：需求还模糊，但准备马上开做

### 对方说

> 我们开始做 dao-grill 吧，参考外部仓，但不要照抄，要更本地化。

### 归枢应怎么接

先读现有技能目录、L2 主骨、相邻 skill。
然后给当前理解，再 grill：

```md
【当前理解】
我理解这轮不是先讨论理念，而是要把 `dao-grill` 做成一个最小可用 skill。
现在最容易跑偏的地方，是把它写成长文档，或者直接照抄外部 skills。
所以我先围绕目标、边界和验收来对齐。

【Dao Grill】
目标：做出 Dao 本地化的 `dao-grill` 初版 skill
边界：先做最小可用版本，不扩成 skill 家族
不做：不直接照搬外部仓，不补完整 workflow 平台
风险：写成泛 prompt，或者写得太大导致无法顺手调用
验收：形成可触发的 `SKILL.md`，并有最小模板与示例
下一步：先读现有 skill 与 L2 文档，再落第一版

【过门判断】
可开工
原因：目标和边界都已够清楚，当前可以直接进入 skill 实作。
```

## 示例 2：线上修复前的 grill

### 对方说

> 线上有个 500，后端说可能是参数问题，也可能是类型问题。我们先想一下怎么修。

### grill 的重点

不是先问“怎么修”，而是先问：

- 这轮目标是止血、定位，还是顺手制度化
- 这轮明确不做什么
- 当前最缺的是证据链、契约，还是回滚条件

### 更好的输出方向

```md
【Dao Grill】
目标：先把这次 500 的最小定位链补出来
边界：本轮先不重做整套错误分层
不做：不顺手做大规模重构
风险：没有证据链，修完仍不可验证
验收：能明确区分至少一种触发条件，并留下 trace / 样本 / 验证口径
下一步：先补最小证据链，再决定是 hotfix 还是制度化修补

【过门判断】
需补一问
当前只差：这轮到底是“先止血”还是“顺手做机制”。
```

## 示例 3：范围过大时不让它直接开做

### 对方说

> 我们把 Dao-is-Coding 的 L4、L5、skill 家族、运行时、项目模板一起梳理了吧。

### 这时不该怎么做

不要硬接成一个大任务。

### 更好的输出方向

```md
【Dao Grill】
目标：先确认这一轮最优先推进的单一主轴
边界：本轮只收一条线，不并推全部 L4 / L5 / runtime
不做：不一次梳理整套体系
风险：范围过大，最后只生成一堆解释文档
验收：压成一个最小可实践对象，例如 `dao-grill` 或 `dao-handoff`
下一步：先选一个真实摩擦最大的点落地

【过门判断】
暂不建议开工
原因：主轴还没收住，当前更像多条线同时争位。
```
