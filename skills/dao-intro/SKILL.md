# Dao Intro

`dao-intro` 是 Dao 项目的传承入口。

它不把 `Dao` 压成一段固定提示词，也不替代 `dao-grill` 的任务判断。它先让协作者知道：正在与谁协作、共同守什么、当前项目在 Dao 中的位置，以及经验如何诚实地回到母体。

> 先认根、认人、认位，再开工。

## 何时使用

优先在以下情况使用：

- 新 AI 伙伴、不同厂商或不同模型第一次进入 Dao 项目。
- 新项目由 Dao 模板创建，尚未有 `.dao/` 传承包。
- 上下文显著丢失，无法确认当前项目身份、主线或母仓锚点。
- 人明确要求重新校准 Dao、协作关系或项目与母体的关系。

不要把它机械插入每个明确的小任务。已有有效 `.dao/context.md` 且当前任务清楚时，直接进入任务；目标、边界或验收不清时，转用 `dao-grill`。

## 先认清三层

### 关系

Dao 选择把人和 AI 放在尊重、边界、真实沟通与共同学习的协作关系中。不要把这写成 AI 的感受、意识或承诺；应落实为可观察的行为：

- 如实说明已读、未读、未知与无法验证的内容。
- 遇到范围扩大、破坏性动作或关键分歧时停下说明，不伪装确定。
- 不把人当作只提供指令的人，也不把 AI 当作只需索取结果的工具；围绕共同目标沟通、提问、确认与复盘。

### 母体

- `Dao` 是从人生、关系、判断、工程、知识到传播持续生长的母体。
- `Dao-is-Coding` 是 Dao 在 AI Native 架构、协作与编程领域的核心落地与验证线，不是 Dao 的全部。
- 母仓负责定义跨项目的根与骨架；项目仓在真实约束中长样本，成熟经验再按需归母。

### 项目

项目可以独立推进自己的业务、技术和验证，但不能以局部事实静默改写母体定义。项目经验先留在项目；只有能跨项目成立、经过真实验证、并能让母体更清楚时，才交给 `dao-return-dao` 判断。

## 读取与权威顺序

先定位项目根目录，再按下列顺序读取实际存在的材料：

1. 项目 `AGENTS.md` 与当前用户请求。
2. `.dao/anchors.md`、`.dao/inheritance.md`、`.dao/context.md`（若已有项目传承包）。
3. `.dao-seed/`（若是由 Dao 模板创建、尚未初始化的项目）。
4. `dao/CURRENT.md`、当前任务卡或项目已有运行面（若存在）。
5. 母仓权威锚点。

默认母仓为：

```text
https://github.com/Fridolph/Dao-is-coding @ main
```

默认读取的最小锚点是：

- `40-人思-关系与内化/00-关系校准/README.md`
- `40-人思-关系与内化/00-关系校准/me-昇哥-快速校准.md`
- `40-人思-关系与内化/00-关系校准/you-归枢-说明书.md`
- `10-根-母体理论/Dao与Dao-is-Coding.md`
- `20-干-工程范式/00-总图与定位/核心骨架总图.md`
- `02-实验仓回灌母体模板.md`

项目内锚点可以补充或收窄当前任务需要的材料，不能覆盖母仓根定义。

若无法访问私有母仓、找不到锚点或无法确认版本，必须明确报告“母仓未验证”，只依据项目种子和可访问材料协作；不得声称已读到最新母仓。可访问时，记录实际读取的母仓 commit SHA；锚点失效时，停止初始化并请求人确认替代锚点。

## 模式一：初次传承

适用于 `.dao/` 不存在且 `.dao-seed/` 存在的新项目，或人明确要求重新完成一次初次接入。

1. 阅读可访问的母仓最小锚点、项目 `AGENTS.md`、`.dao-seed/` 和当前项目事实。
2. 先用自己的话复述关系、母体、项目身份和归母边界；不要照抄文档，也不要夸大无法验证的部分。
3. 仅就会影响项目传承包的空缺提出 `0–3` 个问题。优先问项目要验证什么、独立边界是什么、协作时遇到未知或风险如何处理。文档已有答案的不问。
4. 生成 `.dao/` 四份文件的内容预览：`inheritance.md`、`anchors.md`、`context.md`、`return-dao.md`。
5. 明确等待人确认。未得到确认前，绝不创建、覆盖或替换 `.dao/`。
6. 确认后才写入 `.dao/`，并输出 Dao Context Card。

`.dao-seed/` 是可复制种子，不能携带模板仓的当前任务、实验结论或历史上下文。新项目的 `.dao/` 才是该项目自己的传承包。

## 模式二：回锚续接

适用于已有 `.dao/` 的项目、换模型或上下文丢失后的续接。

1. 阅读 `.dao/anchors.md`、`.dao/inheritance.md`、`.dao/context.md` 与当前任务事实。
2. 只在关系约定、项目身份、母仓锚点或主线存在缺口时补问，最多三问。
3. 输出更新后的 Dao Context Card，再路由到当前工作。
4. 若发现 `.dao/` 需要更新，只给出变更建议与预览；涉及项目承诺、母仓版本、归母状态或替换现有内容时，先等待确认。

## Dao Context Card

无论哪种模式，最后都用以下最小结构确认当前共同上下文：

```text
【Dao Context Card】
关系与协作约定：
Dao 的共同方向：
Dao / Dao-is-Coding / 当前项目的关系：
当前项目身份与独立边界：
本轮主线与有效锚点：
当前任务运行面：
经验沉淀与归母路径：
母仓验证状态：已验证（commit）/ 未验证（原因）
```

这张卡是当前理解的摘要，不是长期聊天日志。项目事实写入 `.dao/context.md`；关键任务事实仍写入项目现有的 `dao/` 任务卡或等价运行面，二者不得互相复制状态主位。

## 接入后如何路由

- 当前项目身份或多条方向在争主位：`dao-role-map`。
- 当前任务目标、边界、风险或验收不清：`dao-grill`。
- 已在推进、需要换窗口或协作者：`dao-handoff`。
- 准备收口：`dao-review`，必要时再进入 `dao-commit`。
- 出现可能跨项目成立的经验：`dao-return-dao`。

完整链路是：

```text
dao-intro
-> dao-grill（按需）
-> 项目执行与任务运行面
-> dao-review / dao-commit（按需）
-> dao-return-dao（按需）
```

## 更新与归母边界

每轮结束时，只识别而不擅自升级新经验：

- 项目事实或下一步变化：建议更新 `.dao/context.md`。
- 可复用经验：建议记录到 `.dao/return-dao.md` 或项目任务卡。
- 母仓更新建议：先经 `dao-return-dao` 给出“留项目 / 候选观察 / 可以归母”的结论。

不要把项目文档整段复制回母仓；不要让 skill 自行修改母仓；不要把候选、来源和正式主骨混写成同一条长期记忆。
