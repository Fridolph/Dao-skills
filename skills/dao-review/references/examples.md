# dao-review 示例集

## 示例 1：功能做完但自测不足

### 对方说

> 我觉得这轮差不多了，帮我看看能不能收。

### 更好的输出方向

```md
【当前总判断】
这轮主线已经接近成立，但现在还不适合直接收口。

【关键发现】
1. 核心实现已完成，但边界自测还没补。

【Dao Review】
是否符合目标：是
是否越界：否
是否完成自测：否
是否有隐藏风险：有，回归影响还没看
是否需要补文档：暂不强制
提交路径：常规提交（自测补完后）
是否产生沉淀候选：暂未形成

【收口结论】
暂不建议收口
原因：当前最少还差一轮能证明它成立的自测。
```

## 示例 2：可以交 review-ready

### 对方说

> 自测过了，我想交给下一位看一下。

### 更好的输出方向

重点不是夸“完成很多”，而是判断：

- 这轮目标是否成立
- 下一位是否不用靠猜就能接 review
- 若正处于合并 / squash，是否形成集成 Dao Commit 锚点

## 示例 3：是否该写 Dao Commit

### 对方说

> 这轮改动不小，要不要直接 Dao Commit？

### grill 的重点

不是改动大就一定 Dao Commit，而是先看：

- 是否处于 `feature -> dev` 或 `dev -> main` 的合并 / squash 边界
- 合并后的净变化是否值得未来回看
- 当前集成单元是否已经在边界内收口
- 是否值得未来回看
- 是否已经在当前边界内收口

### 更好的输出方向

```md
【当前总判断】
这轮已经可以收口；若它正处于集成边界，还要再看合并后的净变化是否值得起锚。

【Dao Review】
是否符合目标：是
是否越界：否
是否完成自测：是
是否有隐藏风险：低
是否需要补文档：视交接情况而定
提交路径：常规提交 / 集成 Dao Commit（按是否处于集成边界判断）
是否产生沉淀候选：`[...]`

【收口结论】
可收口
下一步：若多个普通提交正通过 `feature -> dev` 或 `dev -> main` 形成阶段性净变化，再进入 Dao Commit；否则用普通提交即可。
```
